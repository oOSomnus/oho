# 领域文档

本文件说明工程技能在探索代码库时，如何读取领域文档。

工单、规格说明、地图及其他项目产物使用中文；引用的领域词汇以 `CONTEXT.md` 为准。技能协议规定的固定章节名和标识符保留原文。

## 开始探索前，先读取

- 根目录的 `CONTEXT.md`；或者
- 若根目录存在 `CONTEXT-MAP.md`，按地图找到与当前主题相关的各份 `CONTEXT.md` 并读取；
- `docs/adr/` 中与当前工作相关的 ADR。多上下文布局还需检查 `src/<context>/docs/adr/` 中对应上下文的决策。

如果这些文件不存在，继续工作，不必特别指出缺失，也不要预先建议创建。`/domain-modeling`（由 `/grill-with-docs` 和 `/improve-codebase-architecture` 调用）会在术语或决策实际确定时按需创建它们。

## 本仓库布局：单上下文

```text
/
├── CONTEXT.md
├── docs/adr/
└── src/
```

## 使用术语表中的词汇

在工单标题、重构提案、假设或测试名称等输出中提及领域概念时，使用 `CONTEXT.md` 定义的术语。不要改用术语表明确避免的同义词。

若术语表没有所需概念，应先判断是否使用了项目并不采用的说法；若确有领域词汇缺口，记录下来，交由 `/domain-modeling` 处理。

## 标记 ADR 冲突

如果输出与现有 ADR 冲突，明确指出，不要悄悄覆盖。例如：

> _这与 ADR-0007（事件溯源订单）冲突，但值得重新讨论，因为……_
