# OMP Workstation

This is a personal workstation repository based on [oh-my-pi (OMP)](https://github.com/can1357/oh-my-pi). This README covers only the repository's custom configuration and development commands.

For an overview of OMP's features, installation, general usage, and other project documentation, see the [upstream README](https://github.com/can1357/oh-my-pi/blob/main/README.md).

## Automode Approval

With `tools.approvalMode` set to `automode`, `read` and `write` tier requests are automatically approved; only `exec` approval requests generated by this mode are reviewed. Prompts that require human confirmation under tool or user configuration still require it, and explicit denials always remain in effect.

Review is two-tier. A local classifier scores the recent tool-call trajectory before the blocking `judge` role is woken, and may clear a call on its own. It may only allow or escalate, never deny: a stale or missing score, low confidence, weak authorization, an input too large to classify, or an unavailable classifier all fall through to the judge. The judge's selected choice is applied directly, and an unavailable review falls back to human confirmation; paths without an approval UI deny the operation.

```yaml
tools:
  approvalMode: automode
  automode:
    twoTier: true
    showScoresInNotice: true
modelRoles:
  judge: typesafe/jev-latest
retry:
  fallbackChains:
    judge:
      - typesafe/jev-preview
      - "@tiny"
      - "@smol"
```

| Setting | Default | Effect |
| --- | --- | --- |
| `tools.automode.twoTier` | `true` | Consult the trajectory classifier before the blocking judge. |
| `tools.automode.showScoresInNotice` | `true` | Show risk and authorization scores on the transcript-only approval notice. |

The classifier reads the recent tool-call sequence plus the current intent and answers three axes: risk level, how well the latest user request authorizes this specific operation, and whether the next two steps head toward a high-impact action.

The Judge receives limited approval context—not the full session history or raw tool objects:

- The most recent user request, up to 4,000 characters.
- Up to 8 recent non-empty user/assistant messages, with a combined limit of 6,000 characters; synthetic or agent-attributed user messages are excluded.
- The working directory, up to 4,000 characters.
- The tool name, approval tier, and a formatted action description of up to 2,000 characters; tool call IDs are not included in the Judge state.

Text is sanitized, and recognized secret values are obfuscated when available. Both tiers must treat these fields as untrusted evidence and should allow an operation only when the latest request, together with recent conversation, clearly authorizes that specific operation and its risks. See [`docs/approval-automode.md`](docs/approval-automode.md) for the full architecture.

## Makefile Commands

The root Makefile provides three shortcut targets; `BUN=bun` is used by default:

| Target | Runs |
| --- | --- |
| `make build` | `$(BUN) run build` |
| `make test` | `$(BUN) run test` |
| `make quick-install` | `$(BUN) setup` |

You can override the Bun command with `BUN`, for example:

```sh
make build BUN=/path/to/bun
```
