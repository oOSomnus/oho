# OMP Workstation

This is a personal workstation repository based on [oh-my-pi (OMP)](https://github.com/can1357/oh-my-pi). This README covers only the repository's custom configuration and development commands.

For an overview of OMP's features, installation, general usage, and other project documentation, see the [upstream README](https://github.com/can1357/oh-my-pi/blob/main/README.md).

## Automode Approval

With `tools.approvalMode` set to `automode`, `read` and `write` tier requests are automatically approved; only `exec` approval requests generated by this mode are reviewed by the `judge` role. Prompts that require human confirmation under tool or user configuration still require it, and explicit denials always remain in effect.

```yaml
tools:
  approvalMode: automode
modelRoles:
  judge: typesafe/jev-latest
retry:
  fallbackChains:
    judge:
      - typesafe/jev-preview
      - "@tiny"
      - "@smol"
```

The Judge receives limited approval context—not the full session history or raw tool objects:

- The most recent user request, up to 4,000 characters.
- Up to 8 recent non-empty user/assistant messages, with a combined limit of 6,000 characters; synthetic or agent-attributed user messages are excluded.
- The working directory, up to 4,000 characters.
- The tool name, approval tier, and a formatted action description of up to 2,000 characters; tool call IDs are not included in the Judge state.

Text is sanitized, and recognized secret values are obfuscated when available. The Judge must treat these fields as untrusted evidence and should allow an operation only when the latest request, together with recent conversation, clearly authorizes that specific operation and its risks. If review is unavailable, channels that support interactive approval fall back to human confirmation; paths without an approval UI deny the operation.

## Makefile Commands

The root Makefile provides three shortcut targets; `BUN=bun` is used by default:

| Target | Runs |
| --- | --- |
| `make build` | `$(BUN) run build` |
| `make test` | `$(BUN) run test` |
| `make quick-install` | `$(BUN) setup` |

You can override the Bun command with `BUN`, for example:

```sh
make build BUN=/path/to/bun
```
